## 1. 验证方式

新入口是 [live-model.mjs](../spikes/memory-lifecycle/scripts/live-model.mjs)。自然语言进入真正的 Agent 收件箱；模型自行决定工具名称、参数和调用顺序；验证脚本只投递对话和检查最终数据库状态，没有替模型编写工具调用序列。

实际使用：

- DSH Agent、AgentLoop、Session、SessionProjection。
- DSH SystemPrompt、ToolRuntime 和 defineTool。
- DSH deepseek-account 模型适配器与已有登录凭据。
- DSH 原生 JSONL 会话持久化及 agents.resume()。
- DSH llm-retry 和供应方的有界重试策略。

这次在应用自带运行时的独立进程中组装服务。Desktop 界面、已有 profile、普通会话和插件安装目录保持原有状态；没有把实验安装为公开插件。

## 3. 接入中发现并调整的问题

### 3.1 做法不能变成检索的前置条件

首次模型提炼把“准备离线名单”转成了额外条件 offlineList=true。新项目尚未准备名单，因此严格过滤排除了本来应该推荐的经验。模型随后多次尝试关联，均被代码拒绝，最终超时。

修正是区分**既有场景**与**建议行动**：原型的 requirements 只能取所属项目 context 已明确的键和值；无法验证的新条件返回工具错误，让模型修正。正式版应使用有版本的条件词表，分别表示场景、行动、结果、例外和待确认条件，不能把未知条件直接补成 true。

同一条经验在“已经有名单”和“需要准备名单”两个项目中都可能有用。推荐条件不能要求用户已经完成推荐的行动。

第二次真实对话又发现了跨会话字段漂移：旧项目使用“活动形式、需要签到”，新项目使用“场地、需要准备”。含义相近，数据库键却不相同，旧经验仍然无法通过适用条件检查。

进一步修正为**共享且可配置的条件词表**：工具给出稳定字段名、类型、枚举值，项目写入先校验，记忆再从项目已确认条件中选择。原型的活动资料采用 venue 和 checkIn；校验函数不绑定这两个字段，另用冷链、运输方式、温度等不同领域维度测试。正式版的词表归数据目录管理，新增维度与同义词归一化单独处理。

### 3.2 同义内容不能依赖三元组逐字相等

首次提炼确实为两段同义复盘生成了不同的 subject/value。旧的严格相等算法无法识别这种重复。

新增语义归并计划：模型独立复核完整引用，提交成员 ID、版本和统一命题；代码校验所有者、用途、类型、适用条件、有效时间、当前版本、人工保护、引用集合及撤回规则，再生成一次事务。模型不能提交 SQL，也不能提供自己伪造的记录快照。

归并仍保留一个既有记忆 ID。统一命题和正文、来源集合、被合并条目和关系都进入同一变化包。撤回既恢复不同措辞下各自的命题，也按字段版本保留后来的人工正文。

模型复核是语义判断，代码检查通过不等于语义判断必然正确。当前保存每段支持记忆的引用，不以归并理由删除其中的条件或例外。大范围自动遗忘需要另行评测。

### 3.3 不让模型自行宣布内容已验证

模型提炼一律标记 model-extracted，普通维护不能直接合并。独立整理会话读到具体版本后才可提出归并；提交前发生过编辑就拒绝执行。

owner、sourceId、coverage、请求键由宿主作用域赋值。记忆正文必须能在本次用户消息中找到连续匹配。这个检查能发现伪造引用，不能独自证明模型提炼的全部含义正确；后者由复核与后续独立资料集共同评估。

### 3.4 重试时不能重新生成命令输入

新增重放测试发现：在工具外部生成 recordedAt，会使同一个工具调用在第二次执行时产生不同请求指纹，触发 REQUEST_KEY_REUSED。

已将记录时间移入首次写入的事务内部。幂等输入只包含稳定业务内容；重放复用原记录及时间。请求键使用 sessionId 与 DSH 的 callId，历史发生时间则独立保留。

### 3.5 Agent 空闲不代表任务成功

真实模型服务曾返回 503，Agent 回到空闲但这一轮以 error 结束。验收必须检查 turn/end.reason、工具执行结果和数据库状态，不能仅等待 whenIdle() 就报告成功。

已启用 DSH 自带重试，保持次数和回退时间有界。失败的自然语言轮次与成功轮次分开记录；服务失败不触发重复项目写入或伪造完成答复。

### 3.6 模型摘要不能替代全部来源命题

本次整理模型把两条经验统一为“室内活动需要提前备好离线来宾名单”，省略了“断网时继续核对/签到”的用途。两段支持引用仍在，没有丢失这段文字，但当前原型用统一命题替换 facts，规范命题本身已经变窄。

因此设计增加一项发布前必做调整：**保留原始提炼命题及来源映射，把统一命题作为派生表示；不能仅凭一次模型复核覆盖全部命题。** 在完整性检查通过前，摘要不承担删除来源命题的权限，检索也必须覆盖被摘要省略的命题与必要引用。后续评测要问“为什么准备离线名单”，不能只检查记忆条数下降。

本轮尚未实现这一双层命题结构。现有引用保留和三日差量保障可回查、可撤回；不能将其写成摘要完整性已经通过。

### 3.7 截止时间由程序格式化

数据库的截止时间正确，为 2026-11-06T09:07:00.726Z，即上海时间 2026-11-06 17:07:00.726。模型答复把“17:07”标为 UTC，相差 8 小时。

设计调整为由领域层生成 UTC 时间、用户时区和格式化显示值；通知卡片直接展示该值，模型只描述业务变化。当前原型仍向模型返回毫秒时间戳，本轮没有修正或重新验证自然语言时间展示。72 小时的数据期限和到期拒绝由代码执行，与模型措辞无关。

### 3.8 读取旧目标后，写入必须重新校验

整理后人工改写的第一次调用命中了已被合并的对象，工具返回 OBJECT_NOT_FOUND，没有改动数据库。模型随后调用状态工具，使用保留记录的 ID 与当前 revision 完成修改。撤回后正文和备注都在。

保留记录 ID 与严格版本检查继续采用；正式版可提供只读的旧 ID 归并去向，但不能未经检查把写操作静默转到另一个对象。

## 4. 已补充的回归检查

在前一阶段 23 项基础上新增 7 项，共 30 项：

1. 未复核的模型记忆不能自动合并，复核必须匹配当前版本。
2. 模型批准不能越过事实、条件、引用与人工保护检查。
3. 选择性关联只接纳适用且版本有效的候选，失败时整批回滚。
4. 同义归并后保存每段引用，撤回恢复各自命题并保留人工正文。
5. 拒绝跨所有者、跨条件、重叠归并组及并发人工修改。
6. 工具拒绝伪造身份、覆盖等级、引用和未知条件；同一调用重放保持一次写入。
7. 条件词表适用于可配置的不同领域维度，拒绝字段漂移、错误类型与未声明枚举。

## 5. 后续实现安排

- 条件词表、同名实体、否定、日期精度、跨领域关联和无答案问题使用独立资料集评测。
- 用户改写正文后，将事实、摘要、向量索引标记为待刷新；自动重新提炼不能覆盖人工正文。本轮验证正文和备注的保留，尚未实现整套派生内容刷新。
- 整理会话改由持久调度器投递，加入租约、补处理和单次预算。本轮真实运行了整理 Agent，触发由验证脚本发起。
- 正式状态读取使用有预算的检索与分页；实验使用小型单所有者数据库和全量状态工具。
- 把捕获记忆及所属项目关系收敛为一个领域事务；原型以两个幂等命令写入，重放可补全关系，尚未将这一新组合做进程退出验证。
- 将完成通知接入收件箱；本轮检查事务发件箱和助手答复，没有发送桌面或微信通知。
- JSON 参数字符串改为严格共享类型，接入 Worker、Desktop preset、压缩共存和三系统实机流程。
- 原始命题与派生摘要分层存储，并按明确时区生成通知时间，再验证摘要完整性和用户看到的截止时间。
- 区分项目特定安排与可复用方法；儿童餐券这样的单次安排不能因签到标签相同就自动变成未来项目的通用事实。

普通聊天原文保留 90 天与长期记忆引用分别管理：支持核心记忆的短片段随记忆保留，普通聊天全文按策略回收；三日恢复差量不承担长期知识来源保存。本轮没有执行 90 天原文回收。
