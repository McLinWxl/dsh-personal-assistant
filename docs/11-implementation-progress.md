## 技术方案

业务操作在单个 Worker 内串行处理。写命令按请求标识去重，参数校验、修改、加密差量和通知一起提交。旧版本请求不会覆盖新修改。目录切换与导出会检查任务及会话是否忙碌。

维护直接复用 DSH 模型提供方，不建立包含全部旧记忆的长期原生维护会话。来源提炼、分类刷新、等价归并使用各自命令集合；分类后重新读取版本。无效提案最多修正一次，并发版本变化要求重新读取。原始命题独立保留，派生摘要不能替代它们。人工正文修改后旧派生内容不再召回，等待刷新。

首版使用全文词元、时间与适用条件过滤及关系关联。语义判断由模型完成，没有把向量服务设为迁移的前置条件。条数、输入量、执行时间与恢复资料空间均有预算；超大来源保留待整理，不把截断资料标为完整处理。

任务沿用原生 DSH Agent。执行回合结束后，业务任务进入 needs-review，不能仅凭回合结束就认定实际目标完成。工作流另外核对解释器的执行记录。新建或自动维护的工具默认草稿，用户启用后运行；脚本交给宿主工具检查与执行，不在自动维护器内执行。

微信仅接受绑定主人的完整私聊消息。收件与游标原子保存；发送开始后网络状态不明时保留待核对记录，不自动重复发送。附件使用官方 CDN 加密协议，每个文件最大 20 MB，不自动解压或运行。新连接凭据使用本机系统安全存储，本机重启自动恢复，迁移后重新扫码，不再设置插件口令。通知先进入本地收件箱，再使用有效微信会话上下文发送。

## 单目录与迁移

- manifest.json：数据格式与数据集身份。
- state.sqlite：业务内容、关系、任务、调度和收件箱。
- credentials/rollback.key：撤回差量密钥。
- credentials/vault.enc：仅兼容旧版加密凭据，新连接不写入。
- attachments/：接收的附件，按内容摘要归档。
- projects/workspace/：默认工作目录和成果。
- runtime/：运行锁，不进入导出。

设置中的“导出”生成一致快照。新设备选择导出目录时先验证文件摘要，再启用该目录。也可关闭 DSH 后复制业务目录；不要同时在两台机器写同一目录。

DSH 原生会话日志仍由宿主管理。插件迁移来源归档与业务记忆，普通对话在 DSH 原生页面中继续；插件发起的任务或微信会话在新设备找不到原生记录时重建并接续必要背景。90 天清理覆盖插件归档，不代替宿主历史管理。外部工作目录、外部工具依赖需要在新设备重新指定。

## 实测发现与修复

1. 宿主模块显式列入 peerDependencies，插件加载器才能解析；安装包不依赖开发目录。
2. 按来源类型区分真正用户输入和 DSH 注入的运行时消息，避免将时间提示提炼成个人记忆。
3. 模型参数明确 ISO 时间、时区及重要性范围，并在事务入口再次校验。
4. 分类、归并使用不同命令集合；归并前重新读取分类产生的新版本。
5. Zod 4 的 optional 内默认值会影响部分更新。所有补丁 schema 去掉创建时默认值，未提交字段完整保留。回归测试覆盖项目、任务、系列日程与单次实例。
6. 日期输入即时同步，提交时读取当前控件值，避免显示与提交日期不同。
7. 工作流结果必须是无损 JSON，缺失值显式为 null；业务成功另行核对实际执行记录。
8. 点击“执行”是新的执行指令，任务描述中的历史待办状态不应阻止执行；回合结束与业务成果核对分别记录。

9. 全局会话接入使用消息 ID 去重与回合结束状态，报告和子任务排除在自动提炼之外。
10. 报告回合保留原生工具配置，在执行入口禁止工具操作；避免 DSH 在后续回合重新引入全部延迟工具时拒绝请求。
11. 外部工作目录在新设备不存在时使用数据目录下的工作区，保留原路径供重新指定，不阻断插件启动。
