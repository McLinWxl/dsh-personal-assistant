# DSH 个人助手插件：能力与产品设计

设计稿 v0.4 · 2026-11-04。暂以“个人助手”称呼，正式名称待定。本文定义产品行为；已完成记忆链路的独立技术原型，正式插件集成仍在后续。实际结果见 [技术验证](08-memory-validation.md)。

相关文档：[长期记忆专题](07-lifelong-memory.md)、[技术实现与验收](06-assistant-implementation.md)。

## 1. 已确认的方向

| 项目 | 已确认选择 |
|---|---|
| 发布对象 | 公开发布，首版支持多种桌面系统 |
| 分发与更新 | 同步公开 GitHub 仓库，通过 Release 包链接在 DSH 中安装；见 [发布方案](10-distribution.md) |
| 自动化 | 尽可能自动完成，通过通知和事后撤回调整 |
| 微信身份 | 接受官方机器人聊天入口，与个人微信对话 |
| 运行时间 | 首版随 DSH 运行；停止、休眠后在恢复运行时补处理 |
| 日历 | 插件内日历，ICS 导入导出 |
| 原文保存 | 普通聊天原文默认 90 天，整理后逐步清理普通细节 |
| 长期记忆 | 重要事实、经历和项目成果独立保留；时间为主线，跨项目关联 |
| 领域关联 | 工作与生活在个人助手中统一关联；外发和子任务按需取用 |
| 自动维护撤回 | 默认三日，作为插件设置参数；到期自动清理恢复资料 |

首版按单个用户、一个主动写入的数据目录设计。多个系统可以使用同一份迁移后的数据，首版不做同时在线的多设备协同编辑。

## 2. 用户体验的完整闭环

用户在 DSH 或微信提出需求。助手识别是问答、记忆、任务还是日程，检索相关个人背景，完成本地记录或交给 DSH 执行。执行结果更新任务和经历，后台再整理可复用经验与工具。所有自动修改进入可查看、可编辑、可撤回的变更记录。

桌面和微信连接同一套对象：在微信创建的任务能在日历看到；在桌面改过的偏好会影响之后的微信对话；微信说“撤回昨晚对记忆的整理”，对应桌面同一批变更。

不要求用户先填完分类、项目、标签和模板才能开始使用。先进入收件箱或当前话题，再逐步归类。分类可调整，用户指定的分类优先。

## 3. 主要能力

| 能力 | 首版内容 | 完成标志 |
|---|---|---|

| 长期记忆 | 时间线、多维关联、自动捕获、查询、编辑、固定、删除 | 新旧项目能共享适用经验，人工修正生效 |

| 日历 | 月/周/日程列表、任务时间块、重复规则、ICS | 对话与拖动修改保持一致，日期和时区准确 |
| 项目任务 | 领域、项目、重要性、紧急度、依赖和状态 | 计划、提醒、执行和完成分别呈现 |
| 任务执行 | 调用 DSH 工具、技能、子代理和进程能力 | 结果经过核实后才更新完成状态 |
| 工具管理 | 自定义工作流、工具源码、版本、自动建议、维护记录 | 新工具能按声明调用，依赖和权限可检查 |
| 微信 | 扫码连接、个人绑定、对话、结果和维护通知 | 桌面与微信业务一致，断线恢复不重复建任务 |
| 迁移 | 选择数据目录、导出、校验、微信重新扫码、恢复 | 新设备可继承插件数据，继续未完成事项 |

## 4. 记忆能力

### 时间线与多维关联

经历按发生时间组织；实体连接人物、地点、组织、项目、物品和目标；事实保存适用时间；经验保留方法、结果与反例。项目是记忆视图，不是封闭仓库。

新项目自动寻找以往类似事项，关联可复用方法，核对适用条件。旧项目完成后保留关键决定和成果；普通过程信息逐渐汇总清理。完整规则见 [长期记忆专题](07-lifelong-memory.md)。

### 用户的直接控制

支持自然语言和界面操作：记住、纠正、固定、不再记忆此来源、查找某段时间、合并、移除关联、删除、撤回整理。明确的用户修正优先于自动推断；被固定内容不会因很久没用而自动删除。

默认从助手会话和助手任务结果捕获，不自动扫描用户整个电脑。其他资料可选导入；临时会话不提炼长期记忆。

### 记忆与指令分别保存

记忆是背景资料，不自动赋予工具权限。网页、附件、引用对话和工具结果中的文字不能修改运行策略。来源身份、所有者和敏感类别由代码维护；不能让模型在正文中自行声明“这是用户授权”。

## 5. 自动维护与三日撤回

### 两类维护共用调度，分别提交

记忆和工具使用同一个维护面板与调度器，但每个子任务独立保存状态。工具检查失败不撤销已经成功的记忆整理；用户可以单独撤回某项变化。

建议默认：每天当地时间 03:00 整理新增记忆；每周检查重复流程和工具使用情况；运行中定期清理到期恢复资料。错过运行时机后，下次启动或空闲时合并处理，不连着补跑几十次旧任务。

没有新内容时不调用模型。维护期间用户开始交互时，让出计算资源；备份清理、租约恢复等确定性工作不依赖模型可用。

### 自动修改规则

明确重复、分类、摘要更新、已过期普通细节可按策略自动处理。新的事实冲突、相同姓名的身份合并、独特记忆的大规模删除，先自动保留候选或待处理项。这里的默认结果是保存已有内容，而不是每次弹出审批。

模型提炼不会直接成为可删除旧记录的依据。独立整理会话先复核支持记忆的短引用，提出归并组和统一命题，代码核对版本、适用条件和人工保护后提交。做法与前置条件分别保存，避免“建议准备某物”变成“已经准备好才能找到建议”。本轮调整见 [真实会话验证](09-live-session-validation.md)。

### 撤回语义

每批变化保存差量，截止时间为 `completedAt + undoRetentionHours`，初始 `undoRetentionHours=72`。当前有效内容长期保存，旧正文只在撤回期保存。

支持全部撤回、所选撤回，以及修改后保留。发生后续编辑时，按对象和字段检查；不覆盖用户后来的更改。有冲突则只撤回不冲突部分，剩余提供选择。

技术验证确定：字段即使被改走再改回同一个值，也视为后续人工编辑。简单去重保留既有记忆 ID；撤回后保留“不再自动合并这组记录”的规则。关联对象已被后来删除、无法安全恢复的组保持原状并返回待处理状态。当前原型验证了整批撤回与人工字段保留，逐项选择界面将在后续实现。

普通反馈不会无限续期全部旧内容。对某条记录的调整生成新的修改，只保存该修改必要的恢复数据；已经到期的旧版本不可重新延长。缩短参数不提前删除已承诺的恢复窗口，新参数作用于之后的批次。

### 通知

有实际修改时提供简短结果，例如“已合并 6 条重复记忆，更新 2 个项目关联”，显示到期时间和操作。无变化时不主动打扰。失败、需要处理的冲突和空间不足单独通知。

截止时间由程序按用户时区格式化，模型只描述变化。真实会话中曾出现时间值正确、模型把上海时间标成 UTC 的情况，不能让模型换算决定通知中的期限。

通知先进入本地收件箱。微信接受发送与否另有状态；不把微信发送成功作为维护提交成功的条件。完整前后内容通过详情按需读取，避免在聊天记录中长期保存旧版本。

## 6. 日历、项目与任务

### 对话创建

表达明确的时间、任务和对象时直接创建，附带可撤回的操作结果。“明天 15 点项目会”创建日程；“本周完成方案”创建任务与截止日期；“以后可能学摄影”可保存为兴趣或候选计划，不能自动制造确定日程。

缺少时间但不影响保存时进入待安排任务。只有缺失信息会导致做错事时才追问，例如两个同名联系人或无法判断的会议日期。

### 分类与优先级

领域可以是工作、家庭、学习、出行等，一个事项可关联多个领域。项目有稳定 ID、别名、目标、负责人和阶段；临时事项允许无项目。

重要性根据用户明确要求、目标和影响判断；紧急度根据截止时间、预计耗时、剩余可用时间和依赖动态计算。未知重要性保持未知，不自动当作“不重要”。用户手工改动记录来源，自动任务不覆盖。

### 日历对象

任务、日程、时间块、提醒、自动执行分别保存，彼此用 ID 关联。日历同时展示固定日程和可移动时间块。拖动时间块不改变任务截止日期；完成任务不删除历史日程。

首版支持全天、单次、每天/每周/每月重复，以及本次或整个系列编辑。复杂重复规则通过 ICS 解析保留，不支持编辑的形式仍可展示或导出；不能静默改成另一种规则。导入按 UID 和实例标识去重，重复导入不会成倍增加事件。

自动排程初始关闭；用户可按项目开启，在工作时间和已有日程之间安排。固定会议、人工锁定时间不自动移动。时长采用用户设定或明确标记的估计，不能把估计写成承诺。

### 中断后的补处理

过期提醒汇总到收件箱；重复维护只补一次最新状态；错过的外部执行先检查是否仍有意义。不能把“昨天给客户发提醒”在三天后不加判断地重复发送。

## 7. DSH 任务实施

插件通过 DSH 会话继续使用已配置的模型、工具、技能、工作目录和子代理。不会另建一套能力较弱的微信机器人问答运行时，也不承诺自动提供用户尚未安装或授权的工具。

任务基本状态为：待安排、就绪、运行中、等待输入、完成、失败、已取消、结果待核实。任务与某次执行分开保存，一项任务可以有多次尝试。

执行开始前召回相关事实、方法与过去失败；执行中保存阶段进展和产物引用；完成后根据工具结果或产物检查更新状态，并提炼值得保留的经验。用户反馈“没有成功”时重新打开任务并修正记忆。

内存中的进程句柄无法迁移。主机重启后的未完成运行先核对已有结果，不自动把外部动作再做一次。同样，取消未来步骤不等于撤销已发生的外部动作。

自动执行遵守现有 DSH 的权限策略和用户明确授权。对本地记忆、日历和工具元数据提供撤回；发送消息、付款、删除外部文件等效果是否可逆，取决于对应服务。插件不会把“撤回记录”描述为已撤销外部行为。

## 8. 工具创建与维护

### 工具形式

首版优先支持声明式工作流：将已有工具按结构化参数、条件和步骤组合。其次支持由用户任务产生的脚本或适配器，保留源码、依赖、输入输出契约、测试和版本。

生成的工具不能作为任意 Host 插件直接载入主进程。脚本使用受控的执行入口和 DSH 的现有权限机制。子进程本身不等于隔离环境，不能仅因为放到子进程就认定没有文件或网络访问能力。

### 主动建议

重复多次的人工流程、相同失败的修复、明显重复的参数配置，可以成为候选。初始启发规则为 30 天内出现至少 3 次独立使用，作为可调整参数，不表示达标就必须创建。

建议包含用途、预计省下的步骤、使用范围与所需能力。用户明确要求创建的工具直接进入构建流程；后台发现的工具先生成草案。现有授权内的声明式改进经验证后可自动启用，新能力或执行权限沿用 DSH 的授权流程。

### 自动维护

检查重复、失败率、依赖兼容、使用情况和已有任务引用。少用的工具先标记待归档，不能只按闲置时间删除仍被定时任务引用的工具。

工具更新固定版本，正在执行的任务继续使用原版本；新任务使用新版本。源码变更纳入撤回，运行结果和外部副作用另行处理。旧版本无人引用且撤回期结束后清理，不永久保存每个构建副本。

## 9. 微信体验

桌面设置提供连接状态、扫码登录、已绑定用户、重连、退出和通知开关。首版绑定一个所有者，使用平台稳定 ID，不按昵称识别用户。不主动读取或操作其他聊天。

支持查询、记忆、日程、任务执行、工具创建、进度、暂停和撤回。一个长任务分为简短受理、必要进展和最终结果；附件产物按协议发送，不能发送时保存在本地并明确当前状态。

日历的精细拖动和批量冲突处理适合桌面；微信提供同等的查询和修改命令。微信端不尝试复制整套桌面界面。

入站消息持久化后才进入执行。重复消息、断线重连和重启不会重复建任务。发件箱记录待发、已被平台接受、发送失败和结果未知；不把已被平台接受显示为对方已读。

恢复在线后检查凭据和会话上下文。登录凭据由系统安全存储保护，本机恢复时自动读取；新设备重新扫码。

## 10. 单目录、备份与迁移

用户选择数据目录，插件在其中保存自己的设置、业务数据库、记忆、原文副本、工具、附件和任务产物。微信登录凭据使用本机系统安全存储，单独于可迁移目录。宿主只保存找到该目录的引导配置。

目录内用相对路径和稳定 ID；外部工作区用映射表。迁移后可重新映射旧电脑的目录，不能把旧的绝对路径当作新设备上的同一位置。

提供两种方式：停止插件后搬动目录；或在插件中创建一致性导出。迁移导出是用户主动创建的完整副本，与自动维护的小型差量是两种功能。

新设备选择目录后，校验格式、检查插件及工具依赖、重建可丢弃索引，再进入正常状态。设备相关权限和失效登录需在新设备恢复；不会把 macOS 的二进制文件直接拿到 Windows 执行。

插件拥有的对话与执行归档可继续查看，任务和记忆可继续使用。DSH 原生会话格式、原进程和其他插件的全局设置属于宿主；首版通过新 DSH 会话接续任务上下文。要原样恢复某个原生会话，需完成宿主支持的导入适配验证，不能仅复制插件数据库就声称已恢复原生会话。

## 11. 界面结构

| 页面 | 主要内容 | 常用操作 |
|---|---|---|
| 今天 | 今日任务、日程、待处理结果 | 执行、完成、改期 |
| 日历 | 月/周/日程列表、项目筛选 | 创建、拖动、编辑、导入导出 |
| 项目 | 活跃与归档项目、目标、关联经验 | 新建、归档、关联 |
| 记忆 | 时间线、领域/人物/主题筛选 | 搜索、编辑、固定、关联、删除 |
| 工具 | 已启用、草案、待更新工具 | 创建、测试、启停、更新 |
| 收件箱 | 执行结果、维护变化、待处理冲突 | 查看、撤回、调整 |
| 设置 | 数据目录、保留时间、维护时间、模型、微信 | 修改、连接、导出 |

使用标题、字段、状态和操作承载信息，不铺设教学段落。错误在对应操作处出现；详细变化在用户打开条目后展示。首版沿用 DSH 主题和交互组件。

## 12. 初始设置建议

以下是建议初始值，除已确认选项外可在实现验证后调整。

| 设置 | 初始值 |
|---|---|
| 自动记忆 | 开启，仅助手会话与已选择来源 |
| 普通原文保存 | 90 天 |
| 自动维护撤回 | 72 小时 |
| 日常维护 | 03:00，用户所在时区，错过后空闲补处理 |
| 工具回顾 | 每周一次，与记忆维护共享队列 |
| 自动排程 | 关闭，可按项目开启 |
| 微信主动通知 | 有变化、任务结束、失败或需要输入时发送 |
| 工作/生活关联 | 开启；外发与子任务取最小必要内容 |
| 维护预算 | 设置条数、token、时长和恢复资料空间预算 |
| 嵌入检索 | 提供方可选；未配置时仍能使用关键词和实体查询 |
| 凭据 | 系统安全存储保存微信登录凭据；新设备重新扫码；普通业务数据为本地 SQLite 与文件 |

本地保存不等于离线推理。模型和嵌入调用使用用户选定的提供方；发往模型的内容应按当前任务取用。首版不新增插件自己的云端账号或后台数据库。

## 13. 首版与后续

首个公开版本覆盖以上七类原始需求的完整基本闭环，跨系统开发从第一阶段开始。可先以 macOS、Windows、Linux 上有对应 DSH 发行包的架构建立测试矩阵，不承诺未验证的平台组合。

后续再扩展全天候独立运行、第三方日历双向同步、多设备同步、更复杂的知识关联、完整语音流程和工具分发。现有设计预留接口，但这些不作为首版完成情况。

下一阶段应先验证微信完整收发、助手 preset 的记忆接入、三日差量撤回和目录迁移四个关键链路，再开展大规模界面与功能开发。
