## 2. 场景如何执行

### 起点

虚构旧项目为 2025 年 11 月的工作交流活动，包含两条语义相同且结构化命题相同的签到经验，以及一条不能合并掉的“重名仍需人工核对”经验。另放入适用场景不同、已过期、私密用途和其他所有者的记录。

所有命题和适用条件由测试资料明确提供；本次没有调用模型把自然语言转成这些结构。

### 执行结果

| 步骤 | 观察到的状态 |
|---|---|
| 创建本年度家庭聚会 | 生成独立项目 ID，旧工作项目继续存在，共 2 个项目 |
| 关联过去经验 | 找到 3 条相关记录，包括两条待去重经验与一条关键例外；4 条不适用记录未关联 |
| 自动整理 | 自动发现 1 个重复组，合并后记忆从 7 条变为 6 条；保留 2 条来源记录及关键例外 |
| 关系整理 | 旧项目和新项目的重复引用合并，关系从 5 条变为 3 条 |
| 人工修改 | 修改整理过的正文，并新增本次聚会备注 |
| 撤回 | 恢复被归并的记忆和原有关系，共 5 条关系；保留人工正文与备注；来源集合恢复 |
| 再次操作 | 重复撤回不增加通知；下一次维护不重新执行已撤回的同一归并 |

“2 条来源记录”指结果与复盘两条记录，不能据此推断发生过两次活动。事件数量与来源数量需要分别建模。

人工修改后的正文为：

> 家庭聚会采用纸质名单，同时保留电子名单；重名由现场人员核对。

撤回后该正文和新增备注均保持不变。系统记录正文因后续编辑而保留，而不是笼统显示整条记忆已恢复到旧版本。整理和撤回分别生成一个本地发件箱事件；本次未实际发送桌面或微信通知。

## 3. 需要调整的设计

### 3.1 字段版本取代仅比较字段值

只判断“当前值是否等于整理后的值”不够。用户可能先改成其他内容，再明确改回相同值。此时值虽然相同，仍然包含之后的人工决定。

采用独立字段修改序号。撤回只恢复整理之后没有再次写入的字段；同值重写也更新字段序号。整体对象版本继续承担并发提交检查。已通过同字段、不同字段、反复改值和不同文本内容的测试。

### 3.2 简单归并保留一个既有记忆 ID

首版相同命题的去重优先保留既有记录作为主记录，合入来源并重连引用。这样后来编辑和新建引用有稳定目标，撤回时更容易保留人工内容。

确实需要新建综合摘要时，再采用“新摘要＋来源关联”。它的撤回不能直接删除被用户编辑过的新摘要。本次只验证前一种去重方式；旧 ID 的通用跳转与外部引用恢复还需后续实现。

### 3.3 把整组关系纳入事务和并发检查

不仅检查已有记录的版本，还检查归并对象的关联集合。规划之后新增了一条引用，也必须识别为变化，重新规划。

多个重复组之间存在关联时，要先计算最终关系，再一次提交。撤回所需的项目被后来删除时，整组撤回明确返回依赖冲突，当前数据保持原状。不能先恢复一半，再留下指向不存在对象的关系。

### 3.4 撤回要影响后续自动维护

仅恢复数据会导致第二天重新归并同一组。原型记录不含正文的对象对指纹，阻止同一归并再次自动发生；人工修改的字段另有保护标记。

正式版需要提供清除该规则或重新允许整理的入口。原型验证的是精确对象对，尚未把用户一次撤回泛化成更宽的语义偏好。

### 3.5 文字差量优先在同一数据库中提交

本次将当前数据、变化包、恢复差量与通知发件箱放在同一 SQLite 事务中，真实进程退出测试验证了提交前后的一致性。

因此建议正式版把小型文字差量作为同库加密载荷保存，大附件仍走内容文件和引用回收。相比所有差量均存外部文件，可减少一组文件与数据库协调步骤。原型使用明文差量，没有验证加密、密钥迁移或大附件回收。

### 3.6 中文检索需要预处理和独立质量评测

额外检查发现，直接使用分词结果会因“的”等常见虚词召回无关内容。已对整个检索管线加入通用中英文虚词过滤，相关回归检查通过；同时以实际时间值排序不同偏移量的时间戳，避免按字符串错误排序。

本次自动关联依赖词法匹配及已提供的结构化适用条件。它证明跨年度、跨领域的查找与关联通路可行，不证明任意措辞、隐含关系或模糊项目都能准确理解。下一阶段需要使用人工标注的独立资料集评测模型抽取和语义重排。

## 4. 本轮代码实际覆盖什么

已实现：项目与记忆持久化、词法检索、条件过滤、关系关联、相同结构命题去重、差量记录、字段级撤回、重复请求处理、事务发件箱、到期清理，以及真实 DSH 工具注册适配。

本轮尚未执行：LLM/嵌入调用、自然语言 Agent 对话、模型语义质量评测、后台定时调度、界面交互、微信收发、Windows/Linux 验证、运行中的在线导出和整库迁移加密。目录搬移仅代表同机停止写入后的复制验证。

恢复资料通过专用差量表保存，没有定时复制整个数据库。到期读取被拒绝，启动时删除差量行并执行 WAL checkpoint；不将这个检查描述为存储介质级擦除验证。

该原型同步访问 SQLite、扫描候选记录，以方便验证事务和算法行为；正式版仍需迁入 Worker，增加索引、批次预算、调度租约和来源身份校验。测试专用全量检查工具不进入公开插件。
